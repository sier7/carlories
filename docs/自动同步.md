# 自动同步：Gist 信箱

## 它解决什么

iOS 上网页应用读剪贴板**必须由用户手势触发**，所以「数据自动进到应用里」
在纯网页方案里做不到零点击。

办法是在中间放一个信箱：

```
快捷指令（定时自动跑）--PATCH--> GitHub Gist <--GET-- 应用（打开时自动拉）
```

应用不需要读剪贴板，也就不需要任何点击。

## 为什么是 Gist，而不是自建服务

我们本来做的是 Cloudflare Worker，**在国内用不了**：
`*.workers.dev` 这个域名被 DNS 污染，不只是控制台打不开，手机根本拉不到数据。
（参考：[CloudFlare workers.dev 域名 DNS 污染](https://developer.cloud.tencent.cn/article/2133923)）

Gitee Pages 也已经[下架](https://anttutu.github.io/post/2026-01-26-pages_died/)，
所以国内的静态托管服务也没什么可选。

**而 GitHub 这条路本来就是通的** —— 应用本身就托管在 GitHub Pages 上。

用 Gist 而不是普通仓库文件，是因为三点：

| | Gist | 仓库文件 |
|---|---|---|
| 覆盖写入 | **按文件名覆盖，不需要 sha** | 必须先 GET 拿 sha 再 PUT |
| 快捷指令动作数 | 3 个 | 6 个以上 |
| commit 噪音 | 无 | 每次同步一条 |
| 应用读取需要凭据吗 | **不需要** | 不需要 |

最后一行是关键：**读一个公开 Gist 不需要任何 token。所以写入用的凭据只存在于
快捷指令里，应用里一个口令都没有。**

## 存的是什么

一个纯文本文件，内容是每天两个整数：

```
CAL/TODAY ACT=842 RST=1710
```

就是这样 —— 没有健康记录、没有样本、没有心率睡眠位置。而且它存在**你自己的**
GitHub 账号里。

信箱是**秘密 Gist**：搜索不到，但拿到链接的人能看。链接只在你手上。

---

## 第一步：建一个 Gist 专用 token（约 1 分钟）

打开这个链接（权限已经预选好，只有 `gist` 一项）：

**https://github.com/settings/tokens/new?scopes=gist&description=carlories-mailbox**

点 **Generate token**，复制那串 `ghp_...`。

> ⚠️ **`repo` 权限不包含 `gist`**，这两个是分开的。别拿部署网站用的那个 token
> 来跑这一步。
>
> 这个 token 只能读写你的 Gist，碰不到仓库、碰不到代码。它要**同时**填进
> 快捷指令，所以留着别删。

存成文件 `D:\Carlories\.github-gist-token`（第一行就是 token）。

### ⚠️ 这台机器上的一个网络陷阱

这台机器的 hosts 把 github 域名指到了本地代理（某种 GitHub 加速工具），
代理用自己的证书做中间人。**Node 默认只用自带的 CA 库，不读 Windows 证书库**，
于是会报一个和真实原因毫无关系的错：

```
失败：fetch failed
     code: UNABLE_TO_VERIFY_LEAF_SIGNATURE
```

**这不是网络不通，是证书问题。** 加一个参数即可：

```powershell
node --use-system-ca tools/setup-gist.mjs
```

`npm run setup:gist` / `npm run deploy` / `npm run verify` 里都已经带上这个参数了。

## 第二步：创建信箱

```powershell
node --use-system-ca tools/setup-gist.mjs
```

脚本会创建一个秘密 Gist，把 id 存在 `.gist-id` 里（重复运行会复用，不会越建越多），
然后打印配置串。它还会**用和浏览器完全一样的方式（不带 token）读一次**，
确认应用真的读得到 —— 这是整个方案成立的前提，所以每次都验。

## 第三步：告诉应用

手机上打开应用 → **今日 → 同步设置** → 把上面那行粘进「**Gist 地址或 ID**」
→ **保存配置**。

（也可以直接粘 `https://gist.github.com/你的用户名/那串id`，或者光粘 id。）

保存后，应用每次打开都会自动拉取。**不需要点任何东西。**

## 第四步：改快捷指令，让它往信箱里写

在「同步到 Carlories」里加一个「**获取 URL 内容**」：

| 字段 | 值 |
|---|---|
| 网址 | `https://api.github.com/gists/<你的 gist id>` |
| 方法 | **PATCH** |
| 头部 1 | `Authorization` = `Bearer <刚才那个 token>` |
| 头部 2 | `Accept` = `application/vnd.github+json` |
| 请求体 | **JSON** |

**请求体内容用「文本」动作手打这一整段**，然后把两个方括号换成变量：

```json
{"files":{"carlories.txt":{"content":"CAL/TODAY ACT=[活动统计结果] RST=[静息统计结果]"}}}
```

方括号那两处，拖入对应「计算统计」的结果。它们应该是**纯数字**。

> **不需要搭嵌套字典。** 整段 JSON 就是一个「文本」动作，这是刻意设计的：
> 单行载荷让这件事变成一个字符串拼接，而不是三层字典。

## 第五步：定时

快捷指令 → 自动化 → **+** → 「时间」。iOS 的定时触发器**没有「每小时」选项**，
只能设具体时间点，所以设几条：

```
08:00  每天  立即运行  → 同步到 Carlories
13:00  每天  立即运行  → 同步到 Carlories
19:00  每天  立即运行  → 同步到 Carlories
22:30  每天  立即运行  → 同步到 Carlories
```

每条的「运行前询问」都必须关掉（新版是选「立即运行」）。

## 验证

1. 手动跑一次快捷指令
2. 浏览器打开你的 Gist 页面，看 `carlories.txt` 的内容**是不是合法 JSON 拼出来的那三样**
3. 手机上打开应用 → 今日页 → 应该直接看到今天的消耗，**不需要点任何东西**
4. 消耗那一行下方应显示「**来自信箱** · 刚刚」

## 出问题时

| 现象 | 原因 |
|---|---|
| 快捷指令报错 400 | 请求体不是合法 JSON。多半是变量位置错了，或者变量渲染出来带了单位。把整段文本发我 |
| 快捷指令报错 401 | token 不对，或者没勾 `gist` 权限 |
| 快捷指令报错 404 | Gist id 错了 |
| 应用提示「找不到这个 Gist」 | 配置里的 id 不对 |
| 应用提示「信箱里还没有内容」 | 快捷指令还没成功写过。先手动跑一次 |
| 应用提示「GitHub 接口限流」 | 匿名读接口每小时 60 次。应用已经用 ETag 避免重复计数，正常不会遇到 |
| 消耗一直不更新 | 自动化没跑。去「自动化」里看执行记录；「运行前询问」必须关 |
| 打开应用一直是旧数据 | 快捷指令跑了但没写成功。按上面第 2 步去看 Gist 里的内容 |

## 关掉

应用里 **今日 → 同步设置 → 清空配置框 → 保存配置**。之后就回到手动读剪贴板。

想去掉信箱本身，去 GitHub 上删掉那个 Gist，再吊销那个 token。

## 附：为什么应用不用知道 token

因为它只是 `GET https://api.github.com/gists/<id>`，公开 Gist 匿名可读。
这样即使有人拿到你的手机，也翻不出一个能写你账号的凭据 ——
写入凭据只在快捷指令里，而快捷指令在系统层面受保护。
