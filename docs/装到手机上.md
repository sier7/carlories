# 装到你的 iPhone 上

三步，总共约 10 分钟。第一步在电脑上做，后两步在手机上做。

---

## 第一步：部署（电脑上，约 3 分钟）

### 1. 生成一个 GitHub token

打开这个链接，直接就是配置好的页面（已勾选 `repo` 权限）：

<https://github.com/settings/tokens/new?scopes=repo&description=carlories-deploy>

点最下面的 **Generate token**，复制那串 `ghp_...`（**离开页面就再也看不到了**）。

### 2. 把 token 存到文件

新建文件 `D:\Carlories\.github-token`，把 token 粘进去，保存。

> 这个文件已被 `.gitignore` 忽略，不会被提交。脚本也从不打印它。

### 3. 运行部署

```powershell
cd D:\Carlories
node tools/deploy.mjs
```

脚本会：创建公开仓库 `carlories` → 上传全部文件 → 开启 GitHub Pages → 打印你的网址：

```
https://<你的用户名>.github.io/carlories/
```

**首次发布要等 1–3 分钟。** 之后每次改完代码再跑一次这个脚本即可。

## 第二步：装到主屏幕（手机上，约 1 分钟）

1. 用 **Safari** 打开上面那个网址

   > ⚠️ **必须是 Safari。** Chrome、Edge、微信内置浏览器都装不了网页应用，
   > 它们没有「添加到主屏幕」这个能装成独立应用的操作。

2. 点底部的 **分享按钮**（方框加向上箭头）
3. 往下滑，选 **「添加到主屏幕」**
4. 右上角「添加」

现在主屏幕上就有图标了。**从图标打开，它全屏运行，没有地址栏，和原生应用一样。**

装好之后断网也能用 —— 应用本身和 Service Worker 都缓存在本地了。

---

## 第三步：让健康数据自动流进来（手机上，约 5 分钟）

### 先说清楚能做到哪一步

iOS 上的网页应用**读不到 HealthKit**，这是系统的硬边界，不是没想办法：

- 原生 app 可以读，但需要付费开发者账号（$99/年）—— Apple 官方能力对照表里，
  免费 Apple ID 明确不支持「读健康数据」
- 网页应用读不到，且已安装的网页应用无法被快捷指令唤起
  （WebKit bug [318623](https://bugs.webkit.org/show_bug.cgi?id=318623)）

**但快捷指令是 Apple 官方给健康数据的出口。** 所以分工是：

> **快捷指令负责取数（全自动、定时、不用你管）**
> **应用负责落地（你打开应用时点一次「同步」）**

你唯一要做的操作是那一次点击。不用再打开健康 App 手抄数字。

---

### 3.1 建快捷指令

打开「快捷指令」App → 右上角 **+** → 命名成 `同步到 Carlories`，然后依次添加：

**动作 1** — 搜索并添加「**查找健康样本**」

| 设置项 | 值 |
|---|---|
| 健康样本类型 | `活动能量` |
| 排序方式 | 开始日期 |
| 顺序 | 最新在前 |
| 限制 | **关闭** |
| 筛选条件 | `开始日期` `在今天之后` |

> 如果你的 iOS 版本筛选项叫法不同，选「开始日期 是 今天」也可以。

**动作 2** — 添加「**计算统计**」

- 操作：`求和`
- 输入：会自动填成上一步的结果

**动作 3** — 再加一个「**查找健康样本**」，这次类型选 `静息能量`，其余同上

**动作 4** — 再加一个「**计算统计**」，操作 `求和`

**动作 5** — 添加「**文本**」，内容敲成下面这样（**先手打，再把变量拖进去**）：

```
CAL/TODAY
ACT=
RST=
```

然后：

- 光标放到 `ACT=` 后面 → 点键盘上方的变量区 → 选「**统计结果**」
- 光标放到 `RST=` 后面 → 再选一次「**统计结果**」

> ⚠️ 有两个「计算统计」，要选**对应**的那个。选错了活动/静息会颠倒 ——
> 不过不影响总和，只是分项不准。

> ⚠️ `CAL/TODAY` 就照字面打这四个字母，不要替换成日期。
> 这是故意的：让快捷指令绕开「格式化日期」那个最容易配错的动作。

**动作 6** — 添加「**拷贝到剪贴板**」

现在手动运行一次试试。运行完，剪贴板里应该是一段这样的文本：

```
CAL/TODAY
ACT=842
RST=1710
```

### 3.2 建自动化（让它每天自己跑）

1. 快捷指令 App → 底部「**自动化**」→ 右上角 **+**
2. 选「**时间**」
3. 设为 **每天 22:00**（选一个你通常还没睡、且当天活动基本结束的时间）
4. **确保「运行前询问」是关闭的**（新版 iOS 上是选「立即运行」）

   > 这一步很关键。开着询问的话每次都要你点确认，自动化就失去意义了。

5. 添加动作 → 「**运行快捷指令**」→ 选 `同步到 Carlories`
6. 完成

**建议再加一个**：同样的自动化，设在 **12:30**。这样下午打开应用时看到的是半天前的数据，而不是昨晚的。

### 3.3 在应用里同步

打开主屏幕上的应用 → 今日页 → 点 **「同步健康数据」**

iOS 会弹出「**允许粘贴？**」→ 点**允许**。

然后你会看到「已同步 2026-10-03：活动 842 + 静息 1710 kcal」。

**这就是全部操作：一次点击 + 一次系统确认。**

## 验证清单

按顺序确认，出问题好定位：

- [ ] 网页地址能在电脑浏览器打开，顶部有「今日」和「食物库」两个标签
- [ ] iPhone Safari 打开后能「添加到主屏幕」，图标不是默认的灰色方块
- [ ] 从主屏幕图标打开是全屏，没有地址栏
- [ ] **飞机模式**下从图标打开，应用仍然能起来（证明离线可用）
- [ ] 手动运行快捷指令，剪贴板里是 `CAL/TODAY` 开头的一段文本
- [ ] 在应用里点「同步健康数据」后数字出现，且**与健康 App 里的数字一致**

最后一条最重要。**如果对不上，先别用这个数** —— 净差和将来的预算都建立在它上面。
对不上的常见原因：

| 现象 | 原因 |
|---|---|
| 差约 4.184 倍 | 一个是 kJ、一个是 kcal，在健康 App 里把单位切成千卡 |
| 差约 2 倍 | 手表和 iPhone 的样本被重复计入 |
| 明显偏小 | 「限制」没关，只取到了前几条样本 |

## 常见问题

**应用提示「剪贴板里没有健康数据」**

自动化还没跑，或者剪贴板被别的 App 覆盖了。手动运行一次快捷指令即可。

最省事的办法：把 `同步到 Carlories` 加到**锁屏小组件**或**主屏幕小组件**，
点一下就跑，不用进快捷指令 App。

**提示「读不到剪贴板」**

要么是你点了「不允许粘贴」，要么是页面不在 HTTPS 下。
托管在 GitHub Pages 上就是 HTTPS，正常不会遇到。

**改了代码，手机上没更新**

Service Worker 是「先用缓存、后台更新」策略，所以**第一次打开还是旧版，第二次才是新版**。
退出应用再开一次即可。

**想彻底重来**

删除主屏幕图标 → Safari 设置里清除该网站数据 → 重新添加。
⚠️ 这会**连同你的饮食记录一起删掉**，先导出备份。

---

## 一点实话

`tools/deploy.mjs` 走的是 GitHub REST API 全量上传，没有增量、没有历史 diff。
对个人项目够用，但等你哪天想要真正的版本管理，装个 git 切过去会更好。

另外：**应用代码是公开的，但你的饮食记录始终只在手机本地。**
仓库里没有、GitHub 上也没有 —— 那些数据从未离开过你的手机。
