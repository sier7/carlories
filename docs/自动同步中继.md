# 自动同步：中继方案

## 它解决什么

iOS 上网页应用读剪贴板**必须由用户手势触发**，所以「数据自动进到应用里」
这件事在纯网页方案里做不到零点击。

办法是在中间放一个只做转发的小服务：

```
快捷指令（定时自动跑）--POST--> 中继 <--GET-- 应用（打开时自动拉）
```

于是应用不需要读剪贴板，也就不需要任何点击。

## 存的是什么

**每天两个整数**：活动能量、静息能量，加一个日期。保留 400 天。

不是健康记录，不是样本，没有心率、睡眠、位置、体重。你自己的 Cloudflare
账号里存着你自己的两个数字。

中继同时也是一个**备份** —— 手机上的数据万一丢了，最近 400 天的消耗能从
这里补回来。

---

## 第一步：建一个 Cloudflare API Token（约 3 分钟）

1. 打开 <https://dash.cloudflare.com/profile/api-tokens>
2. **Create Token** → **Create Custom Token**
3. 权限加两项（都想省掉第 4 步的话就加三项）：

   | 类型 | 权限 | 用途 |
   |---|---|---|
   | 账户 | **Workers KV Storage** · 编辑 | 存数据 |
   | 账户 | **Workers Scripts** · 编辑 | 上传中继程序 |
   | 账户 | Account Settings · 读取 | 让脚本自己找到 Account ID（可选） |

4. 点继续、创建，把 token 复制下来（离开页面就看不到了）。
5. 记下 **Account ID**：登录 Cloudflare 后进任意域名，右侧 Overview 页面下方有；
   或者看浏览器地址栏 `dash.cloudflare.com/<这一串就是>`。

> 没有 Cloudflare 账号的话，注册是免费的，Workers 免费额度每天 10 万次请求 ——
> 这个用法一天最多几十次。

## 第二步：存凭据

新建文件 `D:\Carlories\.cloudflare`：

```
第一行：粘贴 API Token
第二行：粘贴 Account ID（如果第 3 项权限加了，这行可以留空）
```

## 第三步：部署中继

```powershell
node tools/deploy-worker.mjs
```

脚本会：找到或创建 KV 命名空间 → 生成同步口令 → 上传中继 → 打开
`workers.dev` 子域 → 打印一条**配置串**。

口令保存在 `.relay-token`，重复部署会沿用同一个，所以不需要每次改。

## 第四步：把配置告诉应用

脚本会打印这样一整行：

```
carlories-relay:v1|https://carlories-relay.xxxx.workers.dev|<口令>
```

复制它 → 手机上打开应用 → **今日 → 同步设置** → 粘进「中继配置」→ **保存配置**。

> 设计成一整行是为了让你在手机上**粘贴一次**，而不是用手机键盘敲一个
> 30 多位的口令。

## 第五步：改快捷指令，让它 POST 上来

在原来的「同步到 Carlories」里，把「拷贝到剪贴板」换成（或再加一个）
「**获取 URL 内容**」：

| 字段 | 值 |
|---|---|
| 网址 | `https://carlories-relay.xxxx.workers.dev/ingest` |
| 方法 | **POST** |
| 头部 | `Authorization` = `Bearer <同步口令>` |
| 请求体 | **JSON** |

请求体三个字段：

| 键 | 值 |
|---|---|
| `date` | 照字面打 **`today`** |
| `activeKcal` | [活动能量的**统计结果**] |
| `restingKcal` | [静息能量的**统计结果**] |

> `date` 写 `today` 是故意的：这样你**不用碰「格式化日期」那个动作**，
> 而那是整个快捷指令里最容易配错的一步。日期由中继按东八区补上。

**保留「拷贝到剪贴板」也没坏处** —— 中继连不上时应用还能从剪贴板兜底。

## 第六步：定时

快捷指令 → 自动化 → **+** → 「时间」。iOS 的定时触发器**没有「每小时」选项**，
只能设具体时间点，所以设几条：

```
08:00  每天  立即运行  → 同步到 Carlories
13:00  每天  立即运行  → 同步到 Carlories
19:00  每天  立即运行  → 同步到 Carlories
22:30  每天  立即运行  → 同步到 Carlories
```

## 验证

1. 手动跑一次快捷指令
2. 电脑上跑 `node tools/verify-site.mjs` —— 只验站点，不验中继
3. 想验中继的话，浏览器打开 `https://<中继地址>/health`，**应该看到 401**
   （没带口令 = 拒绝，这正说明鉴权在工作）
4. 手机上打开应用 → 今日页 → 应该直接看到今天的消耗，**不需要点任何东西**
5. 消耗那一行下方应显示「**来自中继** · 刚刚」

## 出问题时

| 现象 | 原因 |
|---|---|
| 应用提示「中继拒绝了：口令不对」 | 配置串复制不全，或 `.relay-token` 被删过导致口令变了 → 重新跑一次部署脚本、重新粘贴 |
| 应用提示「连不上中继」 | 中继地址写错，或者 Workers 子域没打开（去面板里开） |
| 应用提示「中继上还没有数据」 | 快捷指令还没成功 POST 过。先在快捷指令里手动跑一次，看它报什么 |
| 消耗一直不更新 | 快捷指令的自动化没跑。去「自动化」里看有没有执行记录；「运行前询问」必须关掉 |
| 部署脚本报权限不足 | Token 少了 Workers KV Storage 或 Workers Scripts 的编辑权限 |

## 关掉中继

应用里 **今日 → 同步设置 → 清空配置框 → 保存配置**。之后就回到手动读剪贴板。

中继上的数据仍然在你自己的 Cloudflare 账号里，可以在面板里删掉 KV 命名空间
`carlories-sync`。
